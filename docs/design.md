# 应用管理与上线记录

## 1. 范围与角色

应用管理员维护应用清单；申请人提交已启用应用的上线申请；审核人员通过或驳回；上线登记人员另行登记实际结果。查看、申请、审核、上线登记独立授权，通过和驳回共用审核权限。权限集由管理员通过用户管理明确分配，不向全部登录用户默认授予业务权限。

## 2. 数据

沿用 `releaseApps`（名称、编码、负责人、启用状态、备注）。新增 `releaseRequests` 保存关联应用、申请人 ID 和姓名、申请时间、申请说明、审核人和姓名、审核时间、审核结果和意见、结果登记人和姓名、登记时间、上线说明、实际上线时间。人员和操作时间由服务端生成；成功登记可指定实际上线时间，默认登记时刻。审核通过不填实际上线时间。

申请时保存应用名称快照，历史记录不因应用改名或停用丢失。生命周期日志保存每个动作及操作人和时间。待审核、待上线期间以非空应用锁定键唯一约束防止不同用户或不同提交键重复申请；终态清空该键。所有业务写入与提交回执在同一事务中执行。

## 3. 五状态流程

提交 → 待审核 → 审核通过 → 待上线 → 成功登记 → 已上线。
待审核可驳回至已驳回；待上线可失败登记至上线失败。驳回意见和失败说明必填。审核与结果登记只能在合法源状态执行，生命周期版本条件更新拦截并发决定。已驳回、上线失败后可新建申请，旧申请不可编辑或重新提交，已上线记录保持只读。

## 4. 页面与权限

业务侧提供上线记录列表、详情、新建申请；申请人可以选择已启用应用，无需应用管理权限。应用管理提供关联记录和已启用应用的申请入口。列表按应用和状态过滤、服务端分页；详情展示申请、审核、上线信息和历史。手机使用列表卡片和纵向详情、表单。

服务端独立校验登录、业务权限、启用状态、重复申请和状态流转。页面隐藏无权限操作，直接 API 同样拒绝。系统设置提供流程管理的定义和执行页、标准生命周期图和授权历史。本流程没有可调整业务参数，审核人由审核权限决定。

应用管理的每行操作直接显示“编辑”“删除”，删除紧挨编辑；启用/停用保留在菜单内。删除确认点名应用，沿用 update 权限和提交回执，仅删除应用本身。上线记录保留应用名称快照，不级联、不拦截。取消或删除失败保留原记录。

## 5. 不做

自动部署、通知、多级审批、撤回、取消、原申请编辑重提、附件、版本号和计划上线时间不在本次范围。

## 6. 自动化测试平台入口

系统设置的“业务配置”增加“自动化测试平台”卡片，布局和交互与“应用管理”相同。卡片打开独立页面，内容暂时留白，并保留系统导航和面包屑。访问使用独立的设置读取权限，默认不授予普通用户，可在权限集中单独分配。页面不提供测试配置或执行功能。

## 7. AI 助手

AI 助手用于提问和内容整理，不参与上线申请的提交、审批或状态变更。

### 7.1 入口与使用人群

| 入口           | 谁能使用     | 说明                                                 |
| -------------- | ------------ | ---------------------------------------------------- |
| 顶栏“AI 对话”  | 所有登录用户 | 在任意业务页面打开右侧对话面板                       |
| 应用管理页按钮 | 仅管理员     | 在维护应用清单时直接打开对话面板，用于提问或整理内容 |

### 7.2 模型

- 对话模型在“Agent 管理 › 模型服务”中配置和启用，业务页面不重复维护模型清单。
- 新会话可以选择模型；已有会话可以切换模型，但上下文仍属于当前会话。
- 模型服务的 API Key 只填写在模型服务的专用密钥字段，不写入设计文档、需求或源码。

### 7.3 会话与隔离

- 会话和消息存储在服务端，刷新页面或重新登录后仍可继续历史会话。
- 会话列表只返回当前用户自己的记录。
- 读取会话详情、历史消息、发送消息和停止生成都校验会话归属；直接访问他人的会话返回 403 或 404。
- 不提供会话分享入口，也不创建分享记录。

### 7.4 工具与业务数据

- 本版本不注册任何业务工具，AI 不读取或修改上线记录、应用清单等业务数据。
- 原生会话的工具列表置空，不启用 bash、skill、网页搜索等能力。
- 若后续需要接入业务记录，必须注册最小工具集，并在工具执行时校验当前用户的数据权限。

### 7.5 验收标准

- 顶栏和应用管理页都能打开对话面板。
- 模型选择器列出已启用的对话模型，选择后能收到真实回复。
- 生成过程中可以停止，停止后已生成的内容仍保留在会话中。
- 刷新页面后能从历史列表重新打开会话，并继续追问。
- 两个账号互相看不到对方的会话；直接请求他人的会话被拒绝。
- 对话不会改动任何业务数据。
