# ITAM Lite 系统设计

本文是 ITAM Lite 的系统设计文档，也是后续每个需求的依据。需求与本文冲突时，先更新本文，再改代码。

## 1. 目标

公司约 50 人，IT 设备目前记在共享表格里，谁在用哪台电脑、哪台在维修，只能翻聊天记录。ITAM Lite 要解决三件事：

1. 每台设备只有一条记录，随时能查到位置、使用人和状态。
2. 员工在系统里提交领用申请；需要审批的走审批，发放后台账自动更新。
3. 每个人只看到、只做自己权限内的事，限制在服务端生效，而不是只隐藏按钮。

## 2. 角色

| 角色       | 是谁                | 主要工作                                                   |
| ---------- | ------------------- | ---------------------------------------------------------- |
| 员工       | 公司所有人          | 提交领用申请，查看自己的申请和名下设备，撤回尚未发放的申请 |
| IT 支持    | IT 部门一线人员     | 维护设备台账，为已批准的申请发放设备                       |
| 资产管理员 | IT 部门负责资产的人 | 查看全部设备和申请，审批需要审批的申请，删除设备           |
| 系统管理员 | 初始管理员账号      | 管理用户、角色和权限，调整工作流参数                       |

一个人可以同时拥有多个角色，例如 IT 支持本身也是员工。

## 3. 核心对象

### 3.1 设备

| 字段     | 说明                                  | 规则                                       |
| -------- | ------------------------------------- | ------------------------------------------ |
| 资产编号 | 贴在设备上的编号，如 `IT-2026-0001`   | 必填，全系统唯一，最多 40 个字符           |
| 名称     | 型号或名称，如 `MacBook Pro 14 M4`    | 必填，最多 120 个字符                      |
| 类别     | 笔记本、台式机、显示器、手机、配件    | 必填，五选一                               |
| 序列号   | 厂商序列号                            | 选填；填写时全系统唯一（第一轮试用后补充） |
| 状态     | 在库、在用、维修中、已报废            | 必填，新建设备默认为在库                   |
| 使用人   | 当前使用该设备的人                    | 状态为在用时必填；其他状态必须为空         |
| 位置     | 办公室、楼层或库房，如 `上海 3F 库房` | 选填，最多 120 个字符                      |
| 采购日期 |                                       | 选填                                       |
| 备注     |                                       | 选填，最多 2000 个字符                     |

### 3.2 设备领用申请

| 字段     | 说明               | 规则                                  |
| -------- | ------------------ | ------------------------------------- |
| 申请人   | 提交申请的人       | 系统按当前用户填写，不能替别人申请    |
| 设备类别 | 想领用的设备类别   | 必填，与设备类别一致                  |
| 申请理由 | 为什么需要         | 必填，最多 500 个字符                 |
| 期望日期 | 希望拿到设备的日期 | 选填；不能早于提交日期（第 9 章补充） |
| 状态     | 见第 4 章流程      | 只能由工作流修改                      |
| 审批结果 | 提交时按规则计算   | 系统填写                              |
| 审批意见 | 驳回时必填         |                                       |
| 发放设备 | IT 支持发放时选择  | 发放时必填                            |

## 4. 领用流程

```text
            提交（需要审批）                   批准
  员工 ──────────────────▶ 待审批 ──────────────────▶ 待发放 ──── 发放 ───▶ 已发放
     │                        │                        ▲
     │                        └── 驳回 ──▶ 已驳回      │
     └──────── 提交（无需审批） ────────────────────────┘
  待审批或待发放期间，申请人可以撤回 ──▶ 已撤回
```

规则：

1. **什么时候需要审批。** 满足任一条件即需要审批：申请类别属于“需要审批的类别”（默认笔记本、手机）；申请人名下在用设备已达到“免审批可持有数量”（默认 2 台）。两个参数都是工作流参数，系统管理员可在“工作流管理”中调整，修改只影响之后提交的申请。
2. **谁审批。** 任一资产管理员都可以审批，但不能审批自己提交的申请。驳回时必须填写审批意见。
3. **谁发放。** 拥有 IT 支持角色的人，从同类别、状态为在库的设备中选择一台发放。发放时在同一事务中把设备状态改为在用、使用人改为申请人，同时把申请状态改为已发放。
4. **撤回。** 申请人可以撤回待审批或待发放的申请。已发放、已驳回的申请不能再变更。
5. **历史。** 每次状态变更记录操作人和时间，在申请详情中可见。

### 通知

使用 Core 的通知能力发送站内信，点击消息直接进入申请详情。

| 时机       | 通知谁                                     |
| ---------- | ------------------------------------------ |
| 进入待审批 | 所有资产管理员（申请人本人除外）           |
| 进入待发放 | 所有 IT 支持；经过审批的申请同时通知申请人 |
| 驳回       | 申请人，附审批意见                         |
| 发放       | 申请人，附设备资产编号                     |

站内信发送失败不影响申请本身，失败原因可在“工作流管理”的执行记录中查看。

## 5. 页面

| 页面                        | 谁能打开                  | 内容                                                                                                             |
| --------------------------- | ------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| 设备                        | 员工、IT 支持、资产管理员 | 设备列表：按资产编号、名称、序列号搜索，按状态和类别筛选；新建、编辑、删除按权限显示。员工只看到分配给自己的设备 |
| 设备申请                    | 员工、IT 支持、资产管理员 | 申请列表（含期望日期）和“新建申请”；详情展示流程进度、可执行操作和历史。员工只看到自己的申请                     |
| 收件箱                      | 所有登录用户              | 模板自带                                                                                                         |
| 系统设置 › 用户、角色与权限 | 系统管理员                | 模板自带；为用户分配角色                                                                                         |
| 系统设置 › 工作流管理       | 系统管理员                | 领用流程的流程图、参数和执行记录                                                                                 |

## 6. 权限

|                    | 员工           | IT 支持 | 资产管理员           |
| ------------------ | -------------- | ------- | -------------------- |
| 查看设备           | 仅分配给自己的 | 全部    | 全部                 |
| 新建设备、编辑设备 | 否             | 是      | 是                   |
| 删除设备           | 否             | 否      | 是                   |
| 提交设备申请       | 是             | 是      | 是                   |
| 查看设备申请       | 仅自己的       | 全部    | 全部                 |
| 审批               | 否             | 否      | 是（不能审批自己的） |
| 发放               | 否             | 是      | 否                   |

所有限制都在服务端生效：列表和详情按数据范围过滤，直接调用超出权限的接口返回 403 或 404。页面按同样的结果隐藏按钮，只是为了使用方便。

## 7. 设计规范

公司没有自己的设计规范，沿用 NocoBase 3 内置规范：shadcn/ui 组件、模板主题变量、标准列表、表单和抽屉。不单独修改颜色和字体。界面提供中文和英文。

## 8. 范围

本版本包含：设备台账、设备申请与审批、站内信通知、三个业务角色及其权限、工作流管理。

本版本不做：采购、维修、盘点、报废、软件许可、设备归还、多级审批、部门与组织架构、导入导出、MDM 同步、AI 助手。需要时另提需求。

## 9. 交付步骤与验收

| 步骤         | 交付                         | 怎样算完成                                                                                                                                       |
| ------------ | ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| 1 设备台账   | 设备表、接口和页面           | 管理员能新建、编辑、搜索设备，并按状态和类别筛选；资产编号或序列号重复时在对应输入框旁提示；刷新后数据还在                                       |
| 2 领用与审批 | 申请、流程、通知、工作流管理 | 笔记本申请进入待审批，资产管理员批准后由 IT 支持发放，台账中该设备变为在用、使用人为申请人；显示器申请直接进入待发放；每个环节相关人员收到站内信 |
| 3 角色与权限 | 三个角色和数据范围           | 三个角色分别登录，看到和能做的与第 6 章一致；员工直接调用审批、发放、编辑设备接口被拒绝                                                          |
